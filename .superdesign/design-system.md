# SRT dashboard design system

## Product
An offline vehicle instrument display hosted by a classic ESP32, not a fleet management SaaS. Primary task: glance at GPS speed, accelerator input and a local route map. No Internet dependencies, webfonts, large photographs, 3D rendering, or new heavy UI libraries. System sans and inline SVG/CSS only. Identity is the existing SRT text wordmark; there is no SRT image logo. Do not use Vite or React starter assets as branding.

## Current baseline (reproduction only)
Use actual source layout: dark shell, SRT LOCAL TELEMETRY top rail with ESP32 ACCESS POINT and CAN LOG button; speed dial left, GPS summary center, accelerator dial right; offline route map below; detailed telemetry panels at bottom. Preserve this only in the baseline reproduction. Color tokens: background #050807, shell #0d1211, wells #141a1a/#1b2222, borders #232c2c/#1a2121; text #f2f6f6/#9fb0b0/#6c7c7c; cyan #35c4e8/#6fe0f2, green #46d17f, amber #e2a33c, red #e2565b. System UI font, 14px primary radius. Source CSS is authoritative for baseline.

## Requested redesign direction
A distinctive black-and-orange vehicle cockpit, replacing the earlier graphite/lime proposal. Brand colors are exclusively black and shades/tints of orange: background #080604, deep panel #120b06, raised #211208, edge #4a2811, muted #b97643, primary #ff8a24, bright #ffae68, pale orange text #ffd2a6. Do not use white, gray, blue, green, red, lime or unrelated colors anywhere in UI chrome. Errors use prominent orange borders, warning icons and explicit text; never rely on color alone. No photographs, webfonts or external scripts. System UI typography, tabular numeric values, inline SVG. Main speed value 100–180px desktop; small uppercase labels. Spacious asymmetric instrument composition, fine technical rules, intentional orange accents, no generic admin card grid.

The homepage starts as an instrument-only cockpit. NO map is visible initially. One prominent OPEN MAP button switches the whole viewport to the real offline Leaflet map; a clearly labeled CLOSE MAP action and Escape return to the cockpit. No route to diagnostics appears on the homepage. Render map tiles in black/orange tones and retain attribution. Keep map implementation lazy: do not mount/load map tiles until opened; preserve the existing trip track.

A central stylized wheel graphic rotates to the current measured MPU6050 pitch, labeled IMU PITCH with degrees. This is a tilt visualization, NOT measured steering or wheel speed. Only pitch is transmitted by the existing firmware; yaw/roll/steering angle must not be invented. Smooth CSS rotation transitions between valid samples, freeze and visibly mark unavailable/stale data. Avoid endless decorative spinning. Show large GPS speed and compact accelerator meter, trip distance, local clock, GPS signal and heading.

Opening animation: a lightweight typographic SRT wordmark/logo drawn with HTML or SVG strokes, brief orange line reveal and fade into the cockpit (about 1.4 seconds maximum). Play once per browser tab session, allow skip by tap, honor prefers-reduced-motion, never block telemetry polling. Do not invent an image logo or replace the SRT identity. Tiny CSS transforms/opacity only; no video, canvas engine, WebGL or animation library.

Responsive targets: 1280x800 landscape, 800x480 small in-car display, and 390px mobile. Minimum 44px controls, readable contrast, visible keyboard focus, no horizontal page overflow. Modest CSS transitions and motion disabled for reduced-motion users. Missing values use an em dash with a reason.

## /status diagnostics
A separate manually entered URL; absolutely no homepage navigation, hidden shortcut, footer link or button leading here. Can have a return-to-dashboard link. Black/orange visual system, mobile-first layout and plain language.

Top: connection freshness, CAN controller state, active fault/warning count and highest-priority actionable fault. Show explicit OFFLINE, STALE, FAULT, NO FIX, UNKNOWN or ONLINE states using symbols and text; red/green must not be used. Include practical checks only supported by evidence. No-fix is not proof a GPS sensor is disconnected; OFF switches and ignition OFF are normal, not faults.

Node selector: five tappable numbered node buttons/cards showing label, status, last-seen age and issue count. Tapping a node reveals its attached sensors/inputs, current decoded readings, frame IDs, freshness and availability. Use a stacked detail panel on mobile; keyboard accessible selection and aria-pressed. Node 1: accelerator ADC GPIO34, ADC percentage and voltage estimate (fresh received readings cannot prove sensor hardware health). Node 2: PWM GPIO13/14 and active-low reverse relays GPIO33/26; receive-only firmware sends no telemetry, so mark unobservable/unknown, never claim online or failed. Node 3: seven switches with ON/OFF/unavailable and frame freshness. Node 4: GPS fix/satellites/position, MPU6050 pitch/validity, ignition/on-time, hill request and heartbeat errors. Node 5: local CAN controller, filesystem, uptime, WiFi clients, free/minimum heap and TX failures when firmware supplies these values. Do not invent remote hardware checks.

CAN log is central and immediately recognizable, not hidden behind a modal. On phones show readable message cards; desktop can use rows. Each frame has CAN ID, source node, age/time, a plain-language decoded message, severity and optional expandable raw hex/DLC. Filters: exact hex CAN ID, node, text search across readable message/ID/bytes, and issues-only; clearly show active filters and a one-tap reset. Pause freezes the displayed snapshot only; it must be clearly labeled and must not stop CAN reception. Resume restores live display. Keep a bounded 64-frame snapshot; show buffer capacity and filtered count. Offer copy/export the visible snapshot as JSON via browser APIs, without writing on the ESP32. Malformed known frames and unknown IDs have honest explanatory labels; unknown is not automatically an error. No-match and invalid-filter states must be helpful. Explain logs are a bounded recent sample, not a permanent recorder.

Provide a short bounded recent fault transition list and useful details: live/stale distinction per message, last-good age, error reason, expected interval/timeout, and inspect related frames from a node detail. Missing API response invalidates previous online claims. Avoid unbounded histories or continuous JSON exports.

## Runtime constraints
ESP32 classic, No OTA 2MB app / 1.875MiB filesystem partition (0x1E0000 usable partition). Reserve at least 64KiB filesystem overhead in packing estimate; verify actual LittleFS image if tool available. Existing map tiles dominate flash. No new frontend libraries or downloaded fonts. CSS/SVG animations execute in the browser. Share current bounded firmware CAN ring, avoid extra server histories; status-only detailed diagnostics API avoids enlarging every homepage poll. Browser polling must have cleanup, capped retry/backoff, and reasonable frequency. Build and pack assets, compile Node 5 with its actual board/partition options, and report measured sizes; do not promise unlimited memory or infer runtime heap from binary size.
